# 实战接续目标

## 目标

- 以 `operation-log-lab` 为真实对象，把线程池、异步、注解和 Spring 扩展机制转化为亲手实现与测试证据。
- 按 M0—M6 顺序推进；当前只完成 M1 的小循环，不自动跨到 M2。
- 每轮形成“行为契约 → 学习者实现 → 测试 → 解释 → 记录”的闭环。

## 当前上下文

- 教材入口：[`README.md`](../README.md)。
- 完整实战任务书：[`reference/OPERATION_LOG_WORKFLOW.md`](../reference/OPERATION_LOG_WORKFLOW.md)。
- 理论阶段：学习者已明确表示完成。S1—S6有既有问答或跨端总结证据；S7—S8按学习者自报结束，本仓库不伪装成再次逐题验收。
- M0：工程状态 `VERIFIED`；学习状态 `SKIPPED`，因为现有骨架不是学习者亲手实现。
- M1：工程状态 `IN_PROGRESS`；学习状态 `NOT_ASSESSED`。

## 实战规则

1. 学习者亲手写核心实现与测试；助手不直接补全练习答案。
2. 一次只推进一个可验证的小循环，先固定行为契约和不变量。
3. 助手可以检查 diff、运行测试、指出契约不符处，并给一条受限提示。
4. 工程状态和学习状态分开：测试通过不自动等于学习者掌握。
5. 每个阶段结束时要求学习者解释“为什么这样做、换一种方式会怎样、哪里会失败”。

## 范围边界

- 当前不写 AOP、线程池、`@Async` 或配置绑定；这些属于 M2—M6。
- 不引入数据库、Redis、MQ、前端、Lombok、Starter 或通用注解扫描框架。
- 不保存业务参数、返回对象、异常消息等敏感数据。
- 不把本地未推送源码说成网页端已经读取。
